If the passing object is not an instance of Media, what happens?
=> The program will crash with a 'ClassCastException'

What class should implement the Comparable interface?
=> Precisely, all classes that has cost or title (Media, Disc, CD, DVD, Book)


In those classes, how should you implement the compareTo() method to reflect the ordering that we want?
=> For title comparison, return the value of the comparison by title if titles differ. If titles are the same, proceed to cost comparison as a tie-breaker
=> For cost comparison, reverse the process (cost first then title)


Can we have two ordering rules of the item (by title then cost and by cost then title) if we use this Comparable interface approach?
=> No, we can't, since the Comparable interface is designed to define the single "natural ordering" of a class. You can only implement the compareTo() method once in the Media class
=> To solve this, use Comparator instead, and create 2 different comparators based on the two ordering rules we need


Suppose the DVDs has a different ordering rule from the other media types, that is by title, then decreasing length, then cost. How would you modify your code to allow this?
=> Yes, this is allowed since DVD inherits from Media, thus we can simply override the comparision method and redefine for the required ordering rule.
=> However, this may be risky since if the comparison method for DVD is modified to Title - Length - Cost, you have to also handle the situation when a DVD is compared to a different type which does not have Length (e.g. Book).
